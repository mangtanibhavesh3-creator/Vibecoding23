# Reflection – Salon Queue Management System

While developing the Salon Queue Management System, I used an AI coding assistant to help me plan and build parts of the application. It helped me move faster, but I learned that AI-generated code should not be accepted without checking whether it works correctly in the actual project.

One important mistake I learned to watch for was the difference between an application working on my local computer and working after deployment. A page or route may appear to work locally but still fail on the hosted version. This showed me that checking only the local application is not enough. I need to test the deployed link as well, open the important pages directly, and read the browser console and deployment logs when something goes wrong.

I noticed problems by testing the application instead of relying only on the assistant's explanation. When the result did not match the expected behaviour, I needed to provide the assistant with the exact error message, the affected page or route, and what I expected to happen. I also learned to make my prompts more specific: explain the current project setup, describe the problem clearly, ask for the reason before changing code, and request a fix that does not unnecessarily disturb working features.

Overall, this project taught me that an AI assistant is a useful development partner, but I am still responsible for reviewing its suggestions, testing the application, and confirming that the final hosted version works. In future, I will test features and deployment earlier, keep my project documentation updated, and give the assistant clear evidence when asking it to debug an issue.
